# 디자인 작업 하네스

상태: 2026-09-22 실행 가능한 하네스. 토큰 검사, Storybook, Playwright UI 검사와 통합 진입점을 구현했다. 현재 검증 상태는 진행표에 기록하며, 기존 사용자 변경을 보존하면서 [설계안](DESIGN_SYSTEM_PLAN.md)의 구현에 사용한다.

작업 선택과 단계 전환은 [진행 파이프라인](DESIGN_IMPLEMENTATION_PIPELINE.md)을 따르고, 시작·검증·완료 기록은 [진행표](DESIGN_PROGRESS.md)에 남긴다.

## 작업 입력

각 UI 작업은 다음 내용을 먼저 기록한다.

- 사용자 작업: 누가 어떤 상황에서 무엇을 끝내야 하는가.
- 대상: 제품, 화면, 컴포넌트, 현재 버전.
- 상태: 기본 상태와 loading / empty / disabled / error / success 중 필요한 것.
- 디자인 근거: 사용할 토큰·패턴, 기존 사례, 필요한 예외.
- 수용 기준: 화면 모양과 실제 동작을 각각 관찰 가능한 문장으로 작성한다.

예: “GIF 생성 중에는 중복 생성을 막고 취소할 수 있다. 취소 뒤 시간 범위는 유지되며 다시 생성할 수 있다.”

## 실행 순서

1. 기준 확인: 최신 제품 코드, manifest, 기존 변경, 관련 문서를 읽는다. 과거 실행 기록과 현재 검사 결과를 구분한다.
2. 재사용 확인: 토큰과 컴포넌트 목록을 확인한다. 기존 요소로 표현할 수 없는 경우에만 새 요소를 추가한다.
3. 상태 사례 작성: 정상 상태뿐 아니라 오류와 사용 불가 상태의 문구·행동을 정의한다.
4. 구현: 실제 제품과 사례가 같은 React 컴포넌트와 토큰을 사용하게 한다. props·이벤트는 타입으로 정의하고 컴포넌트가 소유한 DOM은 외부에서 수정하지 않는다. 테스트용 서비스 응답은 제품 서비스 어댑터와 분리한다.
5. 검증: 변경 관련 단위 검사 → 사례 동작/접근성/시각 비교 → 패키지 통합 검사 순으로 실행한다. 아직 없는 검사를 실행했다고 기록하지 않는다.
6. 차이 검토: 예상/실제/diff와 키보드 동작을 확인한다. 실패 원인을 해결한 후 필요한 검사만 다시 실행한다.
7. 결과 보고: 변경 이유, 적용 범위, 실행 명령과 결과, 증거 경로, 남은 미확인 항목을 남긴다.

## 변경 규칙

- 토큰화한 범위에서 의미가 같은 새 색상·간격을 임의로 만들지 않는다. 동적 타임라인 좌표 같은 데이터 값은 디자인 상수와 구분한다.
- 공통 컴포넌트 변경 시 소비하는 화면·상태를 함께 검증한다.
- 기준 이미지 갱신은 제품 변화의 검토 결과여야 한다. 테스트 통과를 목적으로 일괄 갱신하지 않는다.
- 시각 사례용 mock 결과를 실제 영상 생성·파일 저장·클립보드 성공으로 보고하지 않는다.
- closed Shadow DOM 검사의 사각지대와 실제 브라우저 검수 범위를 리포트에 명시한다.
- 예외에는 대상, 이유, 검증 방법, 재검토 조건을 붙인다. 예외가 늘어나면 토큰 또는 패턴 설계를 다시 검토한다.
- 서로 다른 프로젝트에 동일 DOM 구조나 프레임워크를 강제하지 않는다. 의미 토큰·상태·상호작용 계약을 공통 기준으로 삼는다.

## GIF 편집기 경계

새 편집 UI는 공통 Button·StatusMessage·Disclosure·TimeField를 조합한다. 타임라인의 기존 컨트롤러는 Timeline 어댑터가 소유한 전용 하위 영역에만 접근한다. 시간 입력을 닫힌 root 안으로 옮기지 않는다. light DOM 슬롯과 스타일 범위, Tab 순환·Escape·포커스 복귀·기존 플레이어 단축키 검사를 함께 유지한다. 실제 생성·저장 검수와 Storybook의 모의 응답을 구분한다.

## 작업 결과 양식

```text

사용자에게 달라지는 점:

실행 검사와 결과:
화면 diff / 리포트 / trace 경로:

미확인 사항과 다음 조치:
디자인 예외 및 근거:
```

## 자동화 구현 시 연결할 계약

아래 명령은 실제 `package.json`에 연결되어 있다. 설치·실행 환경과 결과물은 [실행 안내](DESIGN_RUNBOOK.md)를 따른다.

| 명령 | 책임 |
|---|---|
| `ui:build` | 공통 React 소스의 로컬 확장용 번들 생성 |
| `design:check` | 타입·번들 재현·토큰 참조·스타일·안전한 DOM 계약 |
| `storybook:build` | 제품 React 컴포넌트 기반 Controls·Docs·상태 사례 빌드 |
| `test:ui` | 상태별 동작·접근성·시각 비교 |
| `test:design` | 위 검사와 기존 단위/패키지 통합 검사를 연결하는 단일 진입점 |

`npm run test:design`이 디자인 및 기존 제품 검사를 연결한다. 기존 `scripts/test-local.sh`에도 GIF 단위 검사를 추가했으며, 이 스크립트는 단위+E2E용이다. 디자인 전체 검사는 `./scripts/design-local.sh test:design`으로 실행한다. `npm run test:design:guards`는 다섯 가지 의도적 오류 감지를 별도로 검증한다.
