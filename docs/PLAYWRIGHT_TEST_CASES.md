# Playwright 테스트 항목 및 검증 결과

현재 구현된 브라우저 테스트 **11개**의 목적, 절차, 판정 기준을 정리한 문서다. 항목은 [실제 테스트 코드](../tests/e2e/presets.spec.mjs)를 기준으로 작성했다.

최근 실행은 **2026-09-11, 0.3.0 후보에서 11개 통과·실패 0개·재시도 0회, 약 2분**이다. 이전 2026-09-09 실행에서는 당시 9개가 통과했다.

## 1. 검증 환경과 범위

| 항목 | 구성 |
| --- | --- |
| 실행 도구 | Playwright 1.62.1 |
| 브라우저 | Chromium 151.0.7922.34, headless |
| 운영체제 | macOS arm64 |
| 화면 크기 | 기본 1100 × 800, 모바일 배치 검사 390 × 844 |
| 확장 코드 | 실제 `shared.js`, `panel.js`, `player.js`, `background.js` |
| 테스트용 변환 | 임시 복사본에서 Firefox background를 Chromium service worker로 변환하고 `browser` API 호환 코드를 추가 |
| 페이지·미디어 | 로컬 테스트 페이지, 생성한 무음 미디어를 로드한 HTML 미디어 요소, 실제 TextTrack, 테스트용 CC 메뉴 |
| 저장·통신 | 실제 확장 저장소와 서로 다른 origin의 iframe 사이 확장 메시지 통신 |
| 계정·네트워크 | Submeta 로그인이나 실제 강의 영상 없이 실행. 대상 페이지 요청은 로컬 응답으로 대체하고 그 외 페이지 요청은 차단 |
| 프로필 | 테스트마다 별도 임시 프로필 생성. 재시작 테스트 안에서만 동일 프로필 재사용 |

실제 확장을 브라우저에 로드하는 통합 테스트다. 다만 **실제 Submeta·Cloudflare 서비스나 Firefox에서 실행한 테스트는 아니다.** 배포용 Firefox 파일 자체는 테스트용 변환으로 덮어쓰지 않는다.

## 3. 상세 절차와 판정 기준

### PW-01 — 패널 배치·체크박스·모바일 레이아웃

- **코드명:** `panel layout, neutral checkbox and collapsed details`
- **절차:** 페이지와 플레이어 준비 후 설정 유지를 켠다. 데스크톱 화면을 검사하고 390px 너비로 변경한다.
- **통과 기준:**
  - 체크박스의 `appearance`가 `none`이다.
  - 체크 표시를 그리는 `::before`의 왼쪽 테두리 색이 `rgb(25, 25, 28)`(`#19191c`)이다.
  - 상세 상태 영역은 기본적으로 접혀 있다.
  - 패널 위쪽 좌표가 플레이어 아래쪽 좌표보다 작지 않다.
  - 데스크톱 패널 높이가 140px 미만이다.
  - 390px 화면에서 문서 가로 스크롤 너비가 390px를 넘지 않는다.
- **산출물:** `desktop.png`, `mobile.png`.
- **범위:** CSS 값과 배치 수치 검사다. 기준 이미지와 픽셀을 비교하는 시각 회귀 테스트는 아니다.

### PW-02 — 설정 유지 OFF에서 배속 즉시 변경

- **코드명:** `live speed edit with retention OFF, no reload and no later enforcement`
- **절차:** 유지가 꺼져 있음을 확인하고 현재 문서에 식별값을 넣는다. 하단 배속을 1.5배로 바꾼 뒤, 플레이어의 실제 배속을 수동으로 1배로 바꾼다.
- **통과 기준:**
  - 하단 변경 후 실제 `playbackRate`와 확장 저장값이 1.5다.
  - 문서 식별값이 남아 있어 페이지 새로고침이 없었음을 확인한다.
  - 수동 1배 변경 후 상태에 `자동 적용 꺼짐`이 표시되고 실제 배속은 1배다.
- **범위:** 설정 유지 OFF에서도 편집을 한 번 적용하고, 이후 수동 변경을 덮어쓰지 않는 동작을 관찰한다. 장시간 보존을 측정한 것은 아니다.

### PW-03 — 설정 유지 OFF에서 자막 즉시 변경

- **코드명:** `live CC on, language switch and off with retention OFF`
- **절차:** 기본 유지 OFF 상태에서 CC를 켜고, 언어를 영어로 변경한 뒤 CC를 끈다. 단계 사이에 페이지 새로고침을 호출하지 않는다.
- **통과 기준:**
  - 켜기: 플레이어 메뉴 `Captions:한국어`, TextTrack 모드 `showing`.
  - 언어 변경: 플레이어 메뉴 `Captions:English`, TextTrack 모드 `showing`.
  - 끄기: 플레이어 메뉴 `Captions:Off`, TextTrack 모드 `disabled`.
- **범위:** 메뉴 표시와 실제 트랙 모드를 함께 검사한다. 실제 강의 자막 내용·번역 품질·자막 싱크는 검사하지 않는다.

### PW-04 — 빠른 연속 설정 변경

- **코드명:** `rapid edits keep latest UI, saved value and media consistent`
- **절차:** 하단 배속을 `2 → 0.75 → 1.75 → 1.25` 순서로 연속 선택한다.
- **통과 기준:** 실제 `playbackRate`, 확장 저장소의 `rate`, 하단 선택값이 모두 마지막 선택인 1.25다.
- **범위:** 이 순서에서 최신 값이 남는지를 확인한다. 가능한 모든 동시 편집 조합을 검증하는 부하 테스트는 아니다.

### PW-05 — 브라우저 재시작 후 복원

- **코드명:** `persistent storage survives browser restart and applies on reload`
- **절차:** 유지 ON, 1.75배, 한국어 CC를 설정하고 저장 상태를 확인한다. 테스트 브라우저를 닫은 뒤 동일 프로필로 다시 열어 강의 페이지에 접속한다.
- **통과 기준:** 유지 체크가 켜져 있고 실제 배속이 1.75배이며, 한국어 메뉴와 TextTrack `showing` 상태가 복원된다.
- **범위:** 테스트용 Chromium 확장과 프로필의 재시작 검증이다. Mozilla 서명 패키지의 Firefox 재시작 검증을 대체하지 않는다.

### PW-06 — 30회 페이지 내 영상 전환

- **코드명:** `next lesson, replaced iframe and 30 transitions retain settings without duplicate panels`
- **절차:** 유지 ON, 1.5배를 설정한 후 30회 반복한다. 그중 29회는 URL과 iframe 소스를 바꾸는 다음 강의 동작, 16번째 반복은 iframe 요소 자체 교체다.
- **통과 기준:**
  - iframe 교체 시 이전 프레임이 분리된다.
  - 새 프레임 URL이 iframe 소스와 일치하고 미디어가 준비된다.
  - 매 반복에서 실제 배속은 1.5배이며 패널은 정확히 1개다.
- **범위:** 이 항목은 배속과 패널 중복을 검사한다. 30회 자막 유지, 동일 iframe 안의 video 요소만 교체되는 경우, 실제 강좌 간 이동은 이 테스트에 포함되지 않는다.

### PW-07 — 현재 영상만 해제

- **코드명:** `suspend current lesson and resume automatically for next lesson`
- **절차:** 유지 ON, 1.5배에서 상세 상태를 펼쳐 현재 영상만 해제한다. 실제 배속을 1배로 바꾸고 다음 강의로 이동한다.
- **통과 기준:**
  - 해제 후 `현재 영상 해제` 상태가 표시된다.
  - 수동 변경 후 `1배 · 현재 영상 해제` 상태가 표시된다.
  - 다음 강의에서는 실제 배속이 다시 1.5배가 된다.

### PW-08 — 선택 언어 미제공

- **코드명:** `unavailable language does not silently select another language`
- **절차:** 유지 ON 상태에서 영어만 제공하는 테스트 영상으로 전환한다. 선호 언어가 한국어인 상태로 CC를 켠다.
- **통과 기준:**
  - 하단 언어 항목에 `이 영상 미제공`이 표시된다.
  - 플레이어 메뉴는 `Captions:Off`, TextTrack은 `disabled`다.
  - 상세 상태에 `선택 언어 미제공`이 표시된다.
- **범위:** CC 메뉴는 존재하지만 한국어가 없는 경우다. CC 메뉴 자체가 없는 경우와 구분한다.

### PW-09 — 탭 간 동기화·플레이어 제거

- **코드명:** `settings synchronize to another tab; removal cleans up panel`
- **절차:** 같은 프로필에서 두 번째 강의 탭을 연다. 첫 탭의 배속을 2배로 변경한 후 첫 탭의 iframe을 제거한다.
- **통과 기준:** 첫 탭 실제 배속이 2배가 되고 두 번째 탭의 배속 선택 UI도 2배가 된다. iframe 제거 후 첫 탭의 패널 개수는 0개다.
- **범위:** 두 번째 탭의 설정 UI 동기화를 검사하며 두 번째 탭의 실제 재생 속도까지 검사하지는 않는다.

### PW-10 — 지연된 자신의 저장 이벤트

- **코드명:** `own delayed save event does not cancel a live caption edit`
- **절차:** 테스트용 호환 코드에서 실제 storage 이벤트 전달을 150ms 지연한다. 유지 OFF에서 한국어 켜기 → 끄기 → 다시 켜기를 수행한다.
- **통과 기준:** 실제 메뉴와 TextTrack 모드가 한국어/showing → Off/disabled → 한국어/showing과 일치한다.
- **발견·수정:** 현재 revision만 제외한 첫 수정은 세 번째 편집에서 실패했다. 발행한 revision도 식별하여 이전 저장 이벤트가 새 작업을 취소하지 않게 수정한 뒤 통과했다.

### PW-11 — CC 메뉴 없는 영상

- **코드명:** `video without CC menu reports unsupported while speed still applies`
- **절차:** 유지 ON·1.5배 상태에서 CC 메뉴 없는 테스트 영상으로 전환한다.
- **통과 기준:** 실제 배속 1.5배, 준비 대기 종료 후 `자막 메뉴 없음 · 제어 미지원` 상태. 해당 assertion은 최대 20초 기다린다.
- **실사이트 확인:** Linking Retention with Offense에서 같은 미지원 상태와 1.5배 적용을 관찰했다.

## 4. 공통 검사와 시간 기준

- 각 테스트는 확장을 로드한 후 패널이 표시되는지 확인한다.
- 준비 단계에서 미디어 `readyState > 0` 및 초기 연결 확인 상태 해소를 기다린다.
- 기본 assertion 대기 한도는 8초, 테스트 제한은 30초다. 30회 전환 테스트는 90초 제한이다.
- 따라서 ‘즉시 적용 통과’는 **새로고침 없이 값이 반영됨**을 뜻한다. ‘100ms 이내 적용’ 같은 성능 목표를 측정한 결과는 아니다.
- 주 테스트 페이지에서 수집한 `pageerror`가 없는지 검사한다. 모든 확장·브라우저 로그를 망라한 오류 감사는 아니다.
- 실패 시 화면(`failure.png`)과 실행 trace(`trace.zip`) 저장을 시도한다. 브라우저 시작 자체가 실패한 경우에는 생성되지 않을 수 있다.

## 5. 아직 검증하지 않은 항목

아래는 이번 11개 Playwright 테스트의 통과 범위에 포함되지 않는다.

- 실제 Submeta 로그인·구독 계정에서 Cloudflare 플레이어와 연동.
- Firefox 고유 확장 API·권한 및 Mozilla 서명 패키지 설치/재시작.
- 실제 영상이 재생되는 동안의 끊김, 재생 위치 보존, 자막 동기화.
- 네트워크 지연·오프라인·미디어 로드 실패. CC 메뉴 없는 영상은 PW-11에 추가했다.
- 실제 플레이어 설정 메뉴와의 반복 충돌, 사용자가 메뉴를 열어 둔 상태.
- 같은 iframe 안에서 video만 교체되는 동작의 브라우저 통합 검사.
- 여러 코스·운영체제·브라우저 버전 조합 및 장시간 사용.
- 픽셀 비교를 통한 디자인 회귀 검사와 전체 접근성 검사.

기존 VM 단위 테스트에는 설정값 검증, origin/frame 거부, 충돌 횟수 제한, 미디어 변경 후 재개 등이 별도로 있다. 이들은 위 Playwright 11개에 합산하지 않는다.

## 6. 다시 실행하고 결과 확인하기

현재 작업 환경:

```sh
./scripts/test-local.sh
```

이 명령은 기존 VM 단위 테스트를 실행한 뒤 Playwright 테스트를 실행한다. 새 환경의 설치 방법은 [테스트 실행 안내](../tests/README.md)를 참고한다.

- [HTML 보고서](../playwright-report/index.html): 최근 실행 결과. 실행할 때 갱신되며 Git에는 포함하지 않는다.
- `test-results/`: 화면 캡처 및 실패 기록. 다음 실행에서 교체될 수 있다.
- [테스트 코드](../tests/e2e/presets.spec.mjs), [브라우저·확장 구성](../tests/e2e/harness.mjs), [로컬 페이지·미디어](../tests/e2e/site.mjs), [실행 설정](../playwright.config.mjs).
