# P5 — GIF 편집기 디자인 시스템 적용

2026-09-22 / 개발본 0.4.1. 기존 생성·인코딩·저장 프로토콜을 유지하면서 재생 설정과 같은 React 컴포넌트·토큰·상태 규칙을 GIF 편집기에 적용했다.

## 사용자에게 달라지는 점

- 실행 버튼과 편집창을 재생 설정과 같은 중립색·글꼴 위계·공통 버튼 규칙으로 구성한다.
- 편집 영역과 미리보기/저장 영역을 분리한다. 좁은 화면에서는 한 열로 배치하고 가로 넘침을 막는다.
- 시간 입력 높이·모서리·포커스·오류 표현을 공통 토큰으로 맞춘다. 타임라인의 선택 구간은 기존 의미 토큰 `selection.range`로 표시한다.
- 생성 진행, 취소, 생성 실패, 저장 중/성공/실패, 복사 실패를 문구와 상태 색으로 구분한다.
- 생성·저장·복사 중에는 편집과 중복 작업을 막는다. 생성 취소는 선택 시간을 유지하고, 저장 실패는 생성 결과를 유지해 재시도할 수 있다.
- 보조 앱이 없을 때 복사와 폴더 기억은 비활성화하고 일반 파일 저장을 안내한다.
- Escape 닫기, 슬롯을 포함한 Tab 순환, 실행 버튼으로 포커스 복귀를 지원한다. 모달이 열려 있는 동안 뒤쪽 페이지는 inert로 처리하고 닫을 때 기존 상태를 복원한다.

## 실제 조합과 구현 경계

`ui/gif-components.tsx`의 GifEditor가 공통 **Button, StatusMessage, Disclosure**와 **TimeField, Timeline**을 조합한다. GifLauncher도 같은 Button을 사용한다. Storybook은 이 소스 컴포넌트를 그대로 사용한다.

`extension/gif/panel.js`는 시간 검증, 캡처/인코더, 저장, 클립보드 응답을 React 상태와 콜백에 연결한다. React가 소유한 DOM을 직접 수정하지 않는다. 기존 `capture.js`, 인코더, 저장 전송·권한·무결성 검사 코드는 변경하지 않았다.

타임라인은 동작 보존을 위해 **기존 드래그·구간 계산·썸네일 컨트롤러를 React Timeline 어댑터 안에 유지**한다. 전용 하위 영역만 컨트롤러가 소유하고 React가 생성·동기화·해제를 관리한다. 스타일은 모두 공통 토큰과 기본 버튼 클래스를 사용하며 토큰 검사 대상에 포함했다. 타임라인 내부까지 전부 React JSX로 다시 작성했다고 보지 않는다.

닫힌 Shadow DOM은 유지한다. 시간 입력과 타임라인은 React portal을 통해 light DOM의 이름 있는 슬롯에 배치한다. 플레이어의 키보드 핸들러가 입력 요소를 실제 입력으로 인식하게 하기 위해서다. 포털 스타일은 각 편집기 범위로 한정해 원래 플레이어 입력에 영향을 주지 않는다.

`ui/gif-focus.ts`는 제품과 Storybook에서 같은 포커스 순환 규칙을 사용한다. 제품의 UI 런타임과 GIF 번들은 top document와 플레이어 iframe 양쪽 manifest에 명시하고 실제 패키지 허용 목록에 포함했다. React 런타임은 createPortal 공개 API를 추가했으며 기존 lint 경고 두 위치가 그대로임을 확인하고 정확한 해시만 갱신했다.

## 화면과 상태 사례

- 편집기: `http://127.0.0.1:6006/?path=/story/gif--ready`
- 저장 실패: `http://127.0.0.1:6006/?path=/story/gif--save-error`
- 밝은 테마: `http://127.0.0.1:6006/?path=/story/gif--light`
- 시간 입력 문서: `http://127.0.0.1:6006/?path=/docs/timefield--docs`

GIF 15개 상태: 구간 선택, 영상 준비, 시간 오류, 생성 중, 취소, 생성 실패, 생성 완료, 저장 중, 저장 완료, 저장 실패, 복사 실패, 보조 앱 없음, 폴더 미선택, 밝은 테마, 닫힌 root.

전체 Storybook은 47 stories / 9 docs다. `gif-example.svg`는 **상태 표현용 정적 그림**으로 예시임을 화면에 표시한다. 실제 영상·GIF 생성·다운로드·클립보드 검증 결과가 아니며 제품 패키지에 포함하지 않는다. 새 테스트 영상은 만들지 않았다.

## 검증

- 로컬 UI 67/67: 기존 41개와 GIF 시각 8개·접근성 14개·슬롯/스타일·타임라인·취소/재시도·포커스 4개.
- 기존 실제 Chrome ZIP E2E 12개와 신규 GIF 제품 UI 2개 통과. 새 검사는 닫힌 root + 실제 light DOM 입력, 플레이어 상태 보존, Escape/포커스 복귀, 재열기 시 선택 시간 유지, 모바일 넘침을 확인한다.
- 기존 GIF 범위/썸네일/전송/저장 권한 검사 유지. 새 컨트롤러 단위 3개는 모의 캡처·저장 응답으로 취소, 결과 유지, 저장 재시도, 보조 앱 부재를 검증한다.
- 타입·토큰·재현 가능한 번들 검사 및 계약 검사 6개 통과. 전체 확장 lint는 새 오류·경고 없이 통과했다(기존 React DOM 내부 2건의 정확한 해시/위치 예외 유지).
- 기존 재생 화면 기준 이미지는 변경하지 않았다. GIF의 준비/생성 중/완료/저장 실패를 390·1100 폭에서 새로 촬영하고 시각 검토했다.
- 고정 Linux 환경에서도 UI 67/67과 의도적 오류 5종 감지가 통과했다. 신규 GIF 기준 8개는 전체 요소를 촬영한 후보를 검토한 뒤 등록했으며, 기존 재생 기준은 유지했다. 출처·환경·이미지 해시는 `design/evidence/gif-linux-baseline.json`에 기록했다.

최종 코드 기준 `c3821de`의 [CI 실행](https://github.com/yonghyeun/submeta-playback-presets/actions/runs/35679580781)에서 디자인 및 확장 검증 작업이 모두 성공했다. Chrome ZIP 통합 14개, 단위·lint·의존성 감사·Chrome/Firefox 패키지와 manifest 일치 검사를 포함한다. 이 기록 이후 변경은 결과 문서뿐이다.

## 한계와 다음 단계

실제 ZIP을 쓴 UI 검사는 기존 30초짜리 로컬 미디어 자료를 재사용한다. 생성/저장 컨트롤러 단위와 Storybook 서비스 응답은 모의 값이다. 이번 결과를 로그인된 실제 Submeta에서의 GIF 생성, 실제 Firefox, Mac 보조 앱·Finder·사진 앱 저장/붙여넣기까지 검증한 것으로 보고하지 않는다. 이 실제 환경 검수는 P6이다.

변경 후 개발 확장과 강의 페이지를 다시 로드해야 새 iframe UI 런타임을 읽는다. 확장 버전·ID·저장 키·권한은 유지했고 스토어 배포는 하지 않았다.
