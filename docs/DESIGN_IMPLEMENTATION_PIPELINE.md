# 디자인 시스템 구현 진행 파이프라인

작성: 2026-09-22. 이 문서는 이후 디자인 시스템 작업의 실행 순서와 단계 전환 기준이다. 현재는 파이프라인 설계가 완료된 상태이며 아래 구현 단계는 시작하지 않았다.

설계의 이유와 구조는 [디자인 시스템 설계안](DESIGN_SYSTEM_PLAN.md), 매 작업의 실행 규칙은 [디자인 작업 하네스](DESIGN_HARNESS.md), 실제 진행 상태는 [진행표](DESIGN_PROGRESS.md)에 기록한다. 실행 순서·완료 조건은 이 문서, 실제 상태·증거는 진행표를 기준으로 한다.

## 목표와 범위

Submeta의 재생 설정과 GIF 편집기에 공통 디자인 철학·토큰·UI 규칙을 적용하고, 그 규칙을 지키는지 반복 실행으로 확인할 수 있게 한다. 다른 프로젝트가 확인되기 전에는 Submeta에서 검증 가능한 공통 기반을 만든다. 여러 프로젝트로의 적용 완료는 두 번째 프로젝트 검증 후에만 선언한다.

완료된 시스템은 다음 네 가지를 갖춘다.

1. 디자인 판단에 사용할 원칙과 의미 토큰.
2. 제품과 Storybook에서 공유하는 UI 구현 및 상태별 사례.
3. 시각·접근성·기능 회귀를 검사하고 실패 증거를 남기는 CI.
4. 다음 작업자가 같은 방식으로 변경하고 검증할 수 있는 하네스와 실행 기록.

## 전체 순서

```text
P0 현재 상태와 회귀 기준 확보
 → P1 디자인 원칙과 대표 화면 결정
 → P2 토큰과 첫 공통 UI 구현
 → P3 재생 패널을 제품·Storybook에 연결
 → P4 자동 검증과 CI 연결
 → P5 GIF 편집기까지 적용 확대
 → P6 실제 환경 검수와 운영 인계
 → P7 두 번째 프로젝트 적용 검증 [프로젝트 확보 후]
```

P0~P4가 첫 번째 이정표다. 대표 화면 하나에서 디자인 정의 → 구현 → 자동 실패 감지까지 확인한 뒤 P5로 범위를 넓힌다. P6까지가 Submeta 적용 완료, P7까지가 여러 프로젝트에서 검증된 공통 시스템이다.

## 단계별 작업과 통과 조건

| 단계 | 선행 조건 | 수행할 작업 | 산출물 | 다음 단계로 넘어가는 조건 |
|---|---|---|---|---|
| P0 기준 확보 | 없음 | 작업 트리·버전 기록, 기존 단위/E2E/lint 실행, 화면과 상태 목록 작성, 로컬 GIF 검사 누락 보완 | 현재 상태 기록, 기존 화면, 실행 결과 | 기존 실패와 신규 변경 영향이 구분되고 로컬·CI의 필수 검사 목록이 일치함 |
| P1 디자인 결정 | P0 | 원칙을 관찰 가능한 규칙으로 변환, 재생 패널/GIF 편집기 대표안 비교, 토큰·상태·컴포넌트 계약 작성 | 디자인 결정 기록, 대표 화면, 상태 행렬 | 두 화면에 같은 규칙을 설명할 수 있고 테마·간격·글꼴·포커스·오류 표현이 구체적으로 정해짐 |
| P2 공통 기반 | P1 | 토큰 원본·검증·생성 도입, 버튼/입력/상태 표현 추출, 컨텍스트별 스타일 주입 | 토큰 원본과 생성물, 공통 UI, 토큰 검사 | 같은 입력에서 동일 생성물이 나오고 누락·순환 참조가 실패하며 iframe/Shadow DOM/light DOM에서 토큰이 적용됨 |
| P3 대표 화면 연결 | P2 | 재생 패널 렌더러와 서비스 분리, 제품과 Storybook에서 동일 렌더러 사용, 사례 작성 | 작동하는 재생 패널과 사례 카탈로그 | 사례 HTML 복제 없이 공통 구현을 사용하고 기존 저장·배속·자막·영상 전환 검사가 통과함 |
| P4 검증 자동화 | P3 | 상태·접근성·시각 검사 및 CI 연결, 환경 고정, 기준 이미지 확정, 실패 감지 실험 | 실행 명령, CI 결과, 기준 이미지, diff/trace | 아래 P4 검증 실험이 모두 성공하고 깨끗한 환경에서 문서대로 실행 가능함 |
| P5 GIF 적용 | P4 | Dialog/Timeline/상태·저장 UI에 규칙 적용, 제품 어댑터와 사례 연결 | GIF 상태 사례, 통합 UI, 회귀 결과 | 아래 GIF 필수 상태와 키보드 흐름을 검증하고 기존 기능 회귀가 없음 |
| P6 실제 검수·인계 | P5 | 실제 Firefox/Chrome 검수, 지원되는 Mac 보조 앱 경로 확인, 문서·진입점 정리 | 실제 검수 기록, 실행 가이드, 최종 체크리스트 | 목표 지원 범위에 필수 미확인 항목이 없고 새 작업에서 동일 절차를 재현함 |
| P7 공통성 검증 | P6 + 두 번째 프로젝트 | 공통 토큰·규칙 적용, 제품별 테마/어댑터 분리, 중복·예외 평가 | 두 번째 적용 사례, 공유 범위 결정 | 공통 원본 변경을 양쪽 프로젝트에서 검증하고 제품별 차이를 명시적으로 관리함 |

P0에서 기존 검사가 실패하면 원인과 영향 범위를 먼저 기록한다. 디자인 구현에 직접 영향을 주는 실패는 해결 후 진행한다. 외부 계정이나 실행 환경 때문에 실제 검수가 불가능하면 준비 가능한 작업을 진행하되 해당 검증을 통과로 표시하지 않는다.

### P1에서 정할 디자인 계약

- 원칙별 규칙: 예를 들어 ‘상태의 정직함’은 오류 문구·복구 행동·진행 중 버튼 동작으로 구체화한다.
- 테마: 재생 패널과 GIF 편집기의 밝기, 주 행동과 보조 행동의 강조, 타임라인 선택 색의 의미.
- 기본 값: 글꼴, 글자 크기, 줄 간격, 간격 단계, 모서리, 컨트롤 크기, 포커스 표시.
- 반응형: 폭 390/768/1100px에서 배치, 긴 문구, 가로 넘침, 스크롤 기준.
- 상호작용: hover/focus/disabled/loading/error의 모양과 행동, Tab/Escape/포커스 복귀.
- 예외: 호스트 글꼴·여백 상속, 타임라인 데이터 좌표 등 공통 토큰 적용에서 제외하는 이유.

대표 화면을 준비한 뒤 디자인 판단과 근거를 기록한다. 일반적인 구현 선택은 작업자가 진행한다. 사용자가 명시적으로 결정을 유보한 사항이나 서로 충돌하는 제품 요구만 질문하며, 단계마다 반복 승인을 요구하지 않는다. 사용자 피드백으로 방향이 바뀌면 영향을 받는 토큰·사례·기준 이미지를 함께 갱신한다.

### P3·P5의 필수 상태 행렬

| 대상 | 필수 상태 | 필수 동작 확인 |
|---|---|---|
| 재생 패널 | 불러오는 중, 기본값, 유지 켜짐/꺼짐, 저장 중/성공/실패, 언어 미제공, 플레이어 연결 실패, 현재 영상 해제 | 즉시 적용, 연속 변경, 저장 복원, 영상 전환, 재시도, 중복 패널 방지 |
| GIF 편집 | 편집 전, 시간 입력 오류, 생성 중, 취소 후, 생성 실패, 생성 완료 | 범위 선택, 생성 중 중복 실행 방지, 취소 후 재시도, 입력값 유지 |
| GIF 저장 | 저장 중/성공/실패, 복사 성공/실패, 보조 앱 없음, 폴더 미선택 | 일반 저장, 지원 환경의 폴더 기억·원본 GIF 복사, 복구 안내 |
| 모달·레이아웃 | 열림/닫힘, 좁은 화면, 긴 문구, 키보드 조작 | Tab/Shift+Tab, Escape, 포커스 복귀, 닫힌 편집기가 자막 조작을 방해하지 않음 |

모든 상태는 최소 한 개의 재현 사례와 기대 결과를 갖는다. 대표 기본·오류·진행 중 화면은 세 가지 폭에서 시각 검증하고, 나머지 상태는 관련 폭의 사례로 검증한다. 전체 조합을 무조건 늘리지 않고 공통 변경 시 영향을 받는 사례 집합을 실행한다.

### P4의 실패 감지 실험

일시적인 변경을 넣어 검사가 실패하는지 확인한 뒤 원복하고 전체 관련 검사를 통과시킨다. 실험 변경은 최종 제품에 남기지 않는다.

1. 존재하지 않는 토큰 참조 → 토큰 검사가 정확한 위치와 함께 실패.
2. 의미 있는 버튼 크기·색상 변경 → 시각 비교가 실패하고 expected/actual/diff 생성.
3. 입력의 접근 가능한 이름 제거 → 접근성 검사가 실패.
4. 검증 대상 키보드 조작 차단 → 사용자 동작 검사가 실패.
5. 기존 동작 계약 위반 → 관련 통합 검사가 실패.

기준 이미지 생성과 CI는 같은 OS·브라우저·폰트·locale·timezone·화면 배율을 사용한다. 외부 네트워크와 변동 시간을 UI 사례에서 제어한다. 제품 closed Shadow DOM은 유지하며, 열린 테스트 root의 접근성 검사와 실제 제품 키보드·화면 검사의 범위를 구분한다.

초기 기준 이미지가 없는 상태는 최초 생성 단계로만 다룬다. 화면 검토와 결정 기록을 거쳐 저장한 뒤 일반 CI에서는 이미지가 없거나 달라지면 실패하게 한다. 기준 이미지 갱신은 별도 명시적 작업으로 수행하고 자동으로 실패를 덮어쓰지 않는다.

## 매 작업의 반복 루프

```text
진행표에서 선행 조건을 충족한 작업 선택
 → 변경 범위·수용 기준·검사 목록 기록
 → 기존 구현과 사용자 변경 확인
 → 최소 범위 구현 + 필요한 상태 사례
 → 관련 검사 실행
 → 성공: 증거와 결정 기록 후 완료 처리
 → 실패: 환경/제품/디자인/검사 원인 분류 → 수정 → 관련 검사 재실행
 → 다음 작업 선택
```

상태는 `대기 → 진행 중 → 검증 중 → 완료`로 갱신한다. 외부 조건 때문에 진행할 수 없으면 `차단`과 해제 조건을 기록하고 독립적으로 가능한 작업을 계속한다. 완료한 작업의 전제가 바뀌면 `재검증 필요`로 되돌린다.

UI 렌더러 추출과 스타일 개편은 가능한 한 별도 변경으로 나누어 기능 회귀의 원인을 좁힌다. PR에는 작업 ID, 달라지는 사용자 경험, 전후 화면, 검사 결과, 미확인 범위를 포함한다. 기존 기여 절차에 따라 병합·공개 배포를 처리하며 이 파이프라인 통과 자체를 스토어 배포 완료로 취급하지 않는다.

## 실행 환경과 CI 구성 계약

아래 명령은 구현 목표다. P0에서 현재 실행 가능한 명령을 확인하고, 각 명령을 실제로 추가한 단계에서 진행표에 표시한다.

| 진입점 | 역할 | 도입 단계 |
|---|---|---|
| `npm run design:check` | 토큰 유효성, 생성물 일치, 토큰화한 범위의 스타일 규칙 | P2 |
| `npm run storybook:build` | 공통 제품 렌더러를 사용하는 사례 빌드 | P3 |
| `npm run test:ui` | 빌드된 사례의 상태·접근성·시각 검사; 서버 시작/종료까지 자동 관리 | P4 |
| `npm run test:design` | 디자인 검사·사례 빌드·UI 검사·기존 단위/lint/패키지 E2E를 한 번씩 실행 | P4 |

CI는 기존 `Extension validation`을 유지하면서 새 UI 검증을 별도 작업으로 연결한다. 중복 실행 대신 검사별 책임을 나누고, 두 결과가 모두 성공해야 변경을 완료 처리한다. 원격 필수 검사 설정을 바꾸는 경우 새 검사 이름의 실제 성공 결과를 확인한 뒤 적용 상태를 기록한다. 설정하지 않은 검사를 필수 검사라고 보고하지 않는다.

P4에서 UI 의존성과 브라우저 버전, 폰트 설치, 환경 변수를 고정하고 lockfile로 재현한다. 자동 접근성 검사의 규칙 목록과 기존 예외를 버전 관리하며 새 위반은 실패시킨다. 영상·계정 자료가 필요한 실제 검수는 로컬 UI 사례 CI와 분리한다.

실패 결과물은 HTML 보고서, expected/actual/diff, 필요 시 trace로 보관한다. 현재 CI의 7일 보관 정책을 기본값으로 삼는다. 장기 판단에 필요한 결정·요약은 저장소 문서에 남기고, 실제 계정·영상 정보를 포함하는 결과는 공개 artifact에 업로드하지 않는다.

## 되돌리기와 변경 관리

- 각 단계 시작 시 기준 커밋과 이미 존재하는 작업 변경을 기록한다. 사용자 미커밋 변경을 정리 명목으로 삭제하지 않는다.
- 검증 실패 시 현재 작업 범위만 수정하거나 되돌린다. 검증 전 상태를 기준 이미지로 승격하지 않는다.
- 토큰 이름 삭제·변경은 소비하는 화면과 사례를 함께 이전한다. 호환되지 않는 공통 계약 변경은 결정 기록에 남긴다.
- 디자인 기준 변경은 P1 결정 기록부터 갱신하고, 영향받는 P2~P6 항목을 재검증한다.
- 작업 중단·재개 시 진행표의 다음 행동과 차단 조건을 읽고 이어서 진행한다. 과거 통과 결과가 현재 코드에도 유효한지 확인한다.

## 최종 완료 판정

Submeta 완료는 P0~P6 산출물과 증거가 모두 연결되었을 때 판정한다. 핵심 조건은 공통 원본 사용, 필수 상태 사례, 디자인 위반의 자동 실패, 기존 기능 유지, 실제 지원 환경 검수, 재현 가능한 실행 가이드다. 구현 완료·자동 검사 완료·실제 검수 완료를 각각 기록한다.

다른 프로젝트 경로가 아직 없는 경우 P7은 대기 상태로 남긴다. 이는 Submeta 적용 진행을 막지 않으며, 여러 프로젝트 적용 검증까지 완료했다고 표현하지 않는다.
